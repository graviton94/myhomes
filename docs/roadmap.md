# 우리집요정 출시 로드맵

마지막 갱신: 2026-11-19. 비공개 테스트(1.0.9) 시작 시점의 방향.
`docs/plan.md` 3장의 단계표는 초기 계획이라 지금과 다르다(광고 · 쿠팡 파트너스는 하지 않기로 했다). 앞으로의 순서는 이 문서를 따른다.

## 0. 이 앱이 이기는 지점

- **한 문장:** "어디 뒀더라?"를 검색 한 번으로 끝낸다.
- **다른 앱과 다른 점:**
  - 집 지도 위에 물건이 놓인다.
  - 가족이 같은 집을 함께 본다.
  - 광고가 없고, 먼저 권하지 않는 조용한 앱이다.
  - 계정 없이도 폰 안에서 다 된다.
- **성패를 가르는 것: 처음 며칠 안에 물건이 충분히 들어가느냐.** 물건이 20개쯤 들어가야 찾기가 쓸모 있어지고, 그 전에 지치면 떠난다. 그래서 개발 우선순위는 늘 **"넣기가 덜 귀찮아지는가"**가 먼저다.
- **하지 않을 것:**
  - 광고, 제휴 링크
  - 사용자 데이터를 모아 다른 사람에게 추천하기
  - 묻지 않은 알림 · 제안

## 1. 비공개 테스트 (지금 ~ 14일)

**목표:** 실제 폰에서 깨지는 곳을 찾고, 핵심 흐름(넣기 → 찾기)이 쓰이는지 본다.

**실기기에서만 확인되는 것 (테스트 첫 주에 꼭):**

| 항목 | 누가 | 통과 기준 |
|---|---|---|
| 카카오 · Google 로그인 | 사용자 | 스토어 설치 앱에서 둘 다 됨 |
| 영수증 읽기 · 식품 바코드 | 사용자 | Play 서비스 모델로 읽힘 |
| 구매 (라이선스 테스터) | 사용자 | 한 주머니 사면 가루 +500, 플러스면 1,500 |
| 가족 두 폰 동기화 | 사용자 + 가족 | 넣기 · 옮기기 · 수량이 서로 보임 |
| 업데이트 토스트 | 사용자 | 1.0.9 → 다음 빌드에서 뜸 |
| 지도 편집 두 손가락 | 사용자 | 크기 조절 중 확대해도 안 엉킴 |

**운영 루틴 (Claude):**
- 사용자가 증상을 알려 주면 그날 고쳐 다음 AAB 로 낸다(1.0.10, 1.0.11 …). 테스트 기간에도 새 빌드는 올려도 된다.
- 고칠 때마다: 테스트 추가 → CI → 기기 테스트(device.yml) → AAB.
- Crashlytics 는 사용자가 콘솔에서 보고, 오류가 있으면 화면 캡처나 메시지를 넘긴다.

**끝나는 기준:**
- 데이터를 잃는 버그가 없음
- 위 표 6개 통과
- 테스터 12명이 14일을 채움 (Play 의 프로덕션 신청 조건)

## 2. 출시 준비 (테스트 끝나고 1~2주)

### 반드시 (빠지면 출시 안 함)

1. **App Check 켜기.**
   - App Check 화면에서 "확인된 요청"이 90% 이상인지 본다.
   - 그러면 Claude 가 함수 4개에 `enforce_app_check=True` 를 켜고, 사용자는 Firestore 를 적용한다.
   - 그 뒤로 시험용 APK 는 서버 기능이 막힌다(스토어 내부 테스트 트랙으로 시험).
2. **데이터 백업.**
   - 공유 집 데이터는 지금 Firestore 에만 있다.
   - 매일 자동 내보내기(Cloud Storage, 보관 30일)를 functions.yml 처럼 CI 로 설정한다(Claude).
3. **비용 확정.**
   - Jev 호출 단가를 받으면 `JEV_KRW_PER_CALL` 을 넣고, 플러스 · 한 주머니의 남는 금액을 다시 계산한다.
   - Google Cloud 예산 알림(월 3만 원 · 10만 원)을 둔다(사용자, 콘솔).
4. **개인정보처리방침의 국외 이전 항목 보강.**
   - 개인정보보호법 기준으로 넣을 것: 이전받는 자(Google LLC · TypeSafe), 국가(미국), 항목, 시기 · 방법, 보유 기간.
   - 지금은 "미국 데이터 센터"만 적혀 있다. Claude 가 사이트를 고친다.
5. **판매자 쪽 준비 (사용자).**
   - 유료 상품을 파니 Play 결제 프로필이 필요하다.
   - 국내에서는 보통 사업자등록과 통신판매업 신고가 필요하다. 해당 여부는 사용자가 확인한다.

### 하면 좋은 것

- **프로덕션 단계적 출시:** 20% → 50% → 100%. 사흘씩 Crashlytics 를 보고 넓힌다.
- **스토어 스크린샷 7번째 장 "플러스 · 요정 가루":** 유료 기능이 있다는 걸 미리 보여 주면 별점 1점 리뷰가 줄어든다.
- **리뷰 답변 문구:** 자주 나올 질문 5개(백업, 가족 초대, 가루, 해지, 아이폰)의 답을 미리 써 둔다.
- **Firebase 프로젝트 이름:** 지금 `homefairy-dev` 를 출시에도 그대로 쓴다. 나누면 로그인 · 결제 설정을 전부 다시 해야 해서 손해가 크다. 대신 시험용 데이터(`test:ci-*`)가 실제 사용자와 섞이지 않는지만 확인한다.

## 3. 출시 후 첫 두 달: "넣기가 덜 귀찮게"

우선순위 순. 각 항목은 시안 → 허락 → 패치(CLAUDE.md 순서).

1. **첫 집 채우기 흐름.**
   - 템플릿으로 방을 만든 직후, 방마다 흔한 보관함을 칩으로 고르게 한다(거실 → TV장 · 소파 옆 …). 고른 보관함마다 흔한 물건을 칩으로 고른다.
   - 이름 추천에 쓰는 목록(core `name_ideas.dart`)을 그대로 쓴다.
   - 목표: 처음 5분 안에 물건 20개.
2. **찾기 실패 줄이기.**
   - 검색 결과가 0개일 때 "이걸 찾으셨나요?"(비슷한 이름 · 초성)를 보여 준다.
   - 그래도 없으면 "넣어 두기"로 바로 이어 준다.
3. **대표 목록 키우기.**
   - 테스터 피드백으로 빠진 이름을 채운다. 사용자의 데이터를 모으지 않고, 우리가 고친다.
   - 창가, 세탁기 위처럼 아이콘이 없는 자리는 그림을 더한다.
4. **플러스 가치 보강.**
   - 7일 무료 체험(콘솔 설정만)을 넣는다.
   - 연간 요금제(연 29,000원)는 첫 달 구독 수를 보고 정한다.

## 4. 그다음 (데이터를 보고 정할 것)

- **iOS.**
  - Flutter 라 코드는 대부분 그대로다.
  - 필요한 것: Apple 개발자 계정(연 $99), 카카오 · Google 로그인을 두면 의무인 Apple 로그인, App Store 구독(StoreKit) 서버 확인 추가.
  - Android 유료 전환이 보이면 시작한다.
- **사용량을 아는 방법 정하기 (사용자 결정).**
  - 지금은 분석 도구가 없어서 어떤 기능이 쓰이는지 모른다. 선택지는 둘이다.
    - (가) 지금처럼 모르고 피드백 메일로만 간다.
    - (나) 누구인지 모르는 기능별 횟수만 서버에 센다. 개인정보처리방침 한 줄 추가가 필요하다.
  - 권장은 (나)다. 출시 후 2번(찾기 실패)과 1번(첫 집 채우기)이 효과가 있었는지 보려면 숫자가 필요하다.
- **기능 정리.**
  - 쓰이지 않는 기능(예: 이사 모드, 보고서)은 숨기거나 설정 안으로 옮긴다.
  - 기능이 많은 것 자체가 첫인상을 무겁게 한다.
