핵심 3동작: 넣고 · 옮기고 · 빼기

탭 수가 곧 리텐션

이런 앱이 실패하는 이유는 입력이 귀찮아서입니다. 그래서 세 동작의 탭 수 상한을 정하고, 모든 화면을 이 기준으로 설계합니다. 홈 첫 줄에 세 버튼을 항상 둡니다.

넣기

3탭 이내

  1. 1찍기: 카메라가 바로 열림
  2. 2이름: 최근 이름 칩 탭 또는 입력 (AI 연동 후 자동 추천)
  3. 자동위치: 마지막으로 넣은 보관함이 기본값
  4. 3저장하고 다음 찍기: 서랍 하나를 연속으로 등록

옮기기

물건당 1~2탭 + 일괄 2탭

  1. 1물건 선택: 칸을 길게 누르면 선택 모드. 이후엔 탭으로 계속 선택
  2. 2수량 팝업: 1개 · 절반 · 전부 중 탭. 1개뿐인 물건은 팝업 없이 바로 선택
  3. 반복다음 물건 선택 → 수량 → … 아래 막대에 “3종류 15개” 누적
  4. 3옮기기 → 목적지: 최근 보관함 탭 한 번으로 일괄 이동

빼기

1탭 · 여러 개도 일괄

  1. 1−1 꺼내 쓰기: 물건 카드의 가장 큰 버튼
  2. 1다 썼어요 / 버렸어요: 수량 0으로, 이력에 사유 기록
  3. 일괄옮기기와 같은 선택 모드에서 꺼내 쓰기 · 다 썼어요도 한 번에
  4. 자동최소 수량 아래로 떨어지면 장보기 목록에 추가 제안

이름: 집요정

생김새

  • 얼굴: 동그라미 하나에 세로로 긴 점 눈 두 개. 표정은 눈 모양만으로 바꿈
  • 몸: 테루테루보즈처럼 얼굴 아래로 천이 늘어지고 밑단이 물결 모양. 목에 감색 리본
  • 팔다리: 막대기 선 하나씩. 손에는 별 마법봉이나 상자를 듦
  • 모자: 끝이 살짝 꺾인 마법사 모자에 꿀색 별. 앱 아이콘에도 같은 모자
  • 그림체: 크레용 손그림. 선이 살짝 떨리고 알갱이 질감이 남으며, 모자·상자는 빗금으로 칠하고 볼은 지그재그 낙서
  • 선: 진한 갈색 굵은 선 하나로 그려 작은 크기(24px)에서도 알아볼 수 있게

앱 아이콘

감색 바탕에 요정 얼굴과 모자만 크게. 홈 화면에서 다른 앱과 섞여도 모자 실루엣으로 구분됩니다.

쓰는 규칙

  • 한 화면에 한 번만. 정보보다 앞에 나서지 않기
  • 말풍선은 한 줄, 행동으로 이어지는 말만 (“먼저 먹을 게 3개 있어요”)
  • 장식용 그림은 화면 낭독기에서 숨기고, 말풍선 글자만 읽힘
  • 움직임은 등록 완료 때 한 번 폴짝. 동작 줄이기 설정이면 정지
  • 앱에서는 크레용 질감을 미리 그린 이미지(벡터 + 질감)로 넣어 기기 부담 없이 표시

      맞아요, DB만 같이 쓰면 됩니다

      앱은 화면일 뿐이고 데이터는 Firestore 한 곳에 있습니다. Android에서 옮기면 iPhone 화면도 1초 안에 바뀝니다. Flutter로 같은 코드를 쓰니 화면과 규칙도 똑같습니다.

      같은 사람은 같은 계정

      카카오·네이버 로그인은 서버에서 “kakao:회원번호” 형태의 고정 ID로 Firebase 계정을 만듭니다. 폰을 바꾸거나 iPhone에서 다시 로그인해도 같은 사람, 같은 집입니다.

      iOS 출시 전까지 남는 것

      iPhone 가족은 출시 전엔 앱을 설치할 수 없습니다. 초대코드는 미리 보내 두고, 출시 후 로그인하면 바로 합류합니다. iOS 푸시는 Apple 개발자 계정의 APNs 키를 FCM에 등록하면 같은 서버 코드로 발송됩니다.

      인증은 Firebase가 가장 효율적인가

      결론: 카카오·네이버 둘 다 쓰면 어느 쪽이든 서버 함수가 필요합니다. 그렇다면 동기화·오프라인·푸시가 한 묶음이고 초기 고정비가 없는 Firebase가 가장 적은 코드와 비용으로 끝납니다. 단, Cloud Functions를 쓰려면 Blaze(종량제) 요금제로 바꿔야 하고, 사진 저장소도 Blaze가 필요합니다. 무료 사용량은 그대로 유지됩니다. 계정 합치기는 문자 인증 비용이 드는 휴대폰 번호 대신 설정에서 직접 연결로 갑니다.

      데이터 위치: 미국 us-central1 (확정)

      • Firestore와 사진 저장소 모두 us-central1 단일 리전. 여러 리전 묶음(nam5)은 비용 약 2배라 쓰지 않음
      • 사진 저장 무료 구간(5GB)은 미국 리전에만 있고, 단가도 가장 낮음
      • 한국에서는 서버 왕복이 약 0.15초 늘지만, 기기에 먼저 저장하는 방식이라 체감은 작음. 가족 폰에 반영되는 시간만 조금 늦음
      • 해외 진출 시 DB 하나로 끝. 해외에 사는 가족도 같은 집에 그대로 합류
      • 개인정보처리방침에 국외 이전 고지: 이전 국가(미국), 받는 곳(Google LLC), 항목(계정·물건·사진), 시기와 방법, 보관 기간

      다른 클라우드도 검토했나

      • Supabase: SQL이 자유롭지만 오프라인 동기화와 푸시를 따로 붙여야 함
      • AWS Amplify: 오프라인 동기화는 있으나 설정이 복잡하고 Flutter 지원이 약함
      • 직접 운영(PocketBase 등): 싸지만 장애·백업·보안을 혼자 책임져야 함
      • MongoDB Realm 동기화: 2025년에 서비스 종료. 작은 업체·부가 서비스에 기대는 위험
      • Cloudflare R2: 사진 전송료 0원. 1만 가구 이후 사진 전송비가 커지면 사진만 옮기는 카드로 보관

      냉정한 현실

      2026년 기준 AI로 집 물건을 정리하는 앱은 이미 여럿이지만 크게 뜬 앱은 없습니다. 만들기는 쉽고 자리 잡기는 어렵다는 뜻입니다. 그래서 한국어·가족·카카오가 강점인 국내에서 먼저 리텐션을 증명합니다.

      입력 피로를 이기는 법

      3탭 넣기, 여러 개 골라 일괄 옮기기, 1탭 빼기로 손이 덜 가게 하고, 정식 출시 때는 AI 사진 인식으로 이름 입력마저 없앱니다. 출시 시점에 경쟁 앱과의 차이가 가장 커집니다.
